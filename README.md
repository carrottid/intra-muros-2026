# 인트라 무로스 정산판

연극 〈인트라 무로스(INTRA MUROS)〉 한국 초연(2026.11.10 ~ 2027.2.14, 충무아트센터 중극장 블랙) 관람 기록·정산표 웹페이지.
곤 투모로우 정산판(`../Gone Tomorrow/site`)과 같은 구조이며, 앙상블·페어 정산판 없이 주연 5역 × 3명 캐스트와 기본 정산판 1종만 있습니다.

- 배우 필터 · 캐스팅 스케줄표(NOL 예매 상세 페이지 디자인) · 좌석 입력
- 정산판(캐스트 15명 사진 + 좌석배치도 + 관람 기록) → 고화질 PNG 저장
- 기록은 각자 브라우저에 자동 저장, JSON 저장/불러오기로 백업·이동

## 일정 추가

`js/data.js`의 `SCHEDULE` 배열 끝에 같은 형식으로 행을 추가하면 표·집계·총 회차가 자동 반영됩니다.

```js
{ id: '1215-2000', d: '12.15', w: '화', t: '20:00', cast: ['앙쥬', '케빈', '알리스', '리샤르', '잔느'], first: [0], last: [1], hol: true, mat: true, tags: ['sign'] },
{ id: '1214-off',  d: '12.14', w: '월', off: true },   // 공연 없는 날
```

- `id`는 `MMDD-HHMM` 형식. 좌석 저장 키로 쓰이므로 한 번 정하면 바꾸지 마세요.
- 같은 날 회차가 둘이면 날짜·요일 칸이 자동으로 합쳐집니다(NOL 표와 동일). 첫공·막공 뱃지는 PC·모바일 모두 이름 옆 한 줄에 붙고, 모바일(375px)에서도 일시·시간·배우·좌석이 각각 한 줄로 가로 스크롤 없이 들어갑니다.
- `first` / `last`: 첫공·막공 뱃지를 붙일 역할 인덱스 (0 앙쥬, 1 케빈, 2 알리스, 3 리샤르, 4 잔느)
- `hol`: 공휴일(날짜 빨강), `mat`: 마티네(수 16:00, 표시 변화 없음)
- `tags`: 회차 오른쪽(모바일은 시간 아래)에 붙는 칩. `TAGS`에 정의된 키 사용 (`sign`, `special`, `firstGreet`, `lastGreet`, `gift`). 태그가 하나라도 있으면 열이 자동으로 생깁니다.
- 여러 회차에 걸치는 기간(프리뷰 등)은 표 왼쪽 세로 띠로 표시할 수 있습니다. `BANDS`에 `{ key, label, color, col, from, to }`를 추가하면 됩니다 (`col` 0 = 바깥쪽, 1 = 안쪽 / `from`·`to`는 회차 id). 비어 있으면 띠 열은 그려지지 않습니다.

## 좌석 입력

- 충무아트센터 중극장 블랙은 단층이라 **구역-열-번호** 형식입니다 (예: `B-3-12`, `A-1-5`, `C-7-3`). `b 3 12`, `B구역 3열 12번`, `1F-B-3-12`처럼 써도 자동으로 정리됩니다.
- 좌석배치도 표시를 원치 않으면 `0000`을 입력하세요. 횟수만 집계됩니다.
- 형식이 다르거나 없는 좌석은 저장되지 않습니다(엔터 시 칸이 비워지고 안내가 뜹니다).
- 좌석배치도는 공식 SEATING CHART 이미지를 따릅니다. A·C 구역은 '열'이 세로줄(1번이 뒤쪽), B 구역은 열마다 시작 위치가 다른 부채꼴 배치이며, B 6열 앞 휠체어석 4석은 점선으로만 표시됩니다. 구조는 `js/data.js`의 `SEATS`에서 생성합니다.

## 정산판

- 정산판은 가로형 1종(1500px 폭, PNG 저장은 2배). 3열 격자로 1줄 앙쥬·케빈·알리스, 2줄 리샤르·잔느·좌석배치도(아래에 관람 기록). 사진 15장은 모두 140 × 198px로 같습니다.
- 좌석배치도 색: 1회 흰색 → 같은 자리를 여러 번 갈수록 청록(`ACCENT`, NOL 첫공 뱃지 색)으로 진해짐.
- PNG 저장은 `http(s)://`로 접속했을 때 동작합니다 (파일을 더블클릭해 `file://`로 열면 브라우저 보안 정책 때문에 실패할 수 있음).

## GitHub Pages 배포

곤 투모로우와 같은 방식입니다. 저장소 이름은 `../tools/gh_push.py`의 `REPO`(현재 `carrottid/intra-muros-2026`)를 실제 저장소로 바꿔 쓰세요.

1. GitHub에서 새 저장소 생성 (Public)
2. 이 `site/` 폴더 안의 파일 전부를 저장소 루트에 업로드 (`.github/workflows/pages.yml`, `.nojekyll` 포함)
3. **Settings → Pages → Source = GitHub Actions**
4. `https://<계정>.github.io/<저장소명>/` 에서 접속

이후 사진이나 데이터를 바꿀 때는 해당 파일만 다시 업로드하면 됩니다. CSS/JS를 바꿨을 때는 `index.html`의 `?v=숫자`를 올려야 방문자 브라우저 캐시가 갱신됩니다 (`gh_push.py`는 자동으로 올림).

```
cd site
python3 ../tools/gh_push.py "일정 추가" js/data.js
```

## JSON 불러오기 형식

1. 이 사이트의 「JSON 저장」 파일: `{ "seats": { "1110-2000": "B-3-12", ... } }`
2. 회차 목록 배열: `[ { "sid": "1110-2000", ..., "seats": ["B-3-12"] }, ... ]` — `sid`가 이 사이트의 회차 ID와 같고, `seats` 배열의 첫 좌석을 사용합니다.

어느 쪽이든 없는 좌석·알 수 없는 회차는 걸러집니다.
